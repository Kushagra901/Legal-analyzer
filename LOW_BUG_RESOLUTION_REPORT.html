LOW-01: Replace Lingering Print Statements with Structured Logger Resolved
Label: CODE-STYLE-001-ELIMINATE-PRINTS | Target Files: app/api/v1/routers/documents/*, storage_service.py, ocr_service.py

Problem: Router helper functions and storage/OCR services contained raw print() statements writing unformatted strings to standard output. This bypassed structured log formatters, correlation IDs (X-Request-ID), log-level filtering, and Sentry breadcrumb collection.

Remediation: Initialized standard module loggers (logger = logging.getLogger(__name__)) across all modules. Converted diagnostic prints to logger.info() and caught warnings to logger.warning(). Preserved strict confidentiality by logging only document_id references without raw document text.

logger = logging.getLogger(__name__) logger.info("Storage service initialized with provider: %s", provider) logger.warning("OCR processing warning for document %s: %s", document_id, err)

Verification: Unit tests in tests/test_logging.py passed; codebase inspection confirmed zero unmanaged print calls.

LOW-03: Inject Permissions-Policy Header in Security Middleware Resolved
Label: SEC-HDR-001-PERMISSIONS-POLICY | Target Files: app/core/security_headers.py, tests/test_security_headers_and_rate_limit.py

Problem: Security headers middleware omitted a Permissions-Policy HTTP header, leaving browser hardware APIs (camera, microphone, geolocation, payment) unrestricted.

Remediation: Configured Permissions-Policy header in SecurityHeadersMiddleware.dispatch() to explicitly restrict sensitive device APIs:

response.headers["Permissions-Policy"] = "camera=(), microphone=(), geolocation=(), payment=()"

Verification: pytest tests/test_security_headers_and_rate_limit.py verified all HTTP responses return the header.

LOW-04: Modernize docker-compose.yml and Fix Volume Pre-Creation Dependency Resolved
Label: DEVOPS-COMPOSE-001-CLEANUP | Target Files: docker-compose.yml, backend/Dockerfile

Problem: docker-compose.yml specified deprecated version: '3.8' and declared n8n_data: external: true, causing docker compose up to fail if the volume was not manually created in advance. The backend container also lacked a healthcheck.

Remediation: Removed version: '3.8', converted n8n_data to a standard managed volume (n8n_data:), and added a HEALTHCHECK instruction to the backend Dockerfile targeting /health.

HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \ CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')" || exit 1

Verification: Verified compose configuration adheres to current Compose Specification without warnings.

LOW-07: Enforce Unique Constraint on Document Chunk Indexes Resolved
